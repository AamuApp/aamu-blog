<p><strong>Short answer:</strong> How Aamu.app can export daily team backups as readable JSON files to S3-compatible object storage.</p>
<p>Aamu can back up workspace data to object storage your team controls.</p><p>Aamu.app supports daily team backups to S3-compatible storage. A team can connect its own object storage bucket, enable backups, and let Aamu export changed workspace data as structured JSON files once per day.</p><p>The backup contains structured JSON you can inspect, archive or use in a migration.</p><h2>Why S3-compatible backups</h2><p>S3-compatible storage is a useful backup target because it is widely supported. The same basic integration model works with AWS S3 and many compatible platforms such as object storage from cloud providers, infrastructure hosts, and self-hosted S3-compatible systems.</p><p>The bucket can be managed with the team's normal storage policies: retention rules, replication, access logging, lifecycle rules, or whatever the chosen platform supports.</p><h2>What gets backed up</h2><p>Aamu's daily backup focuses on the workspace data that teams usually need if they want to inspect, migrate, audit, or recover operational context.</p><p>The current backup set includes:</p><ul><li><p><strong>Projects</strong>, including basic project metadata and users.</p></li><li><p><strong>Docs</strong>, including searchable document content.</p></li><li><p><strong>Tasks</strong>, including title, content, owner, status, tags, comments, and timestamps.</p></li><li><p><strong>Posts</strong>, including content, author, comments, and timestamps.</p></li><li><p><strong>Helpdesk</strong>, including tickets, chats, chat messages, customers, comments, status, tags, participants, and timestamps.</p></li><li><p><strong>Emails</strong>, including message title, content, recipients, contact, type, comments, and timestamps.</p></li><li><p><strong>Chats</strong>, including rooms and chat messages.</p></li><li><p><strong>Meetings</strong>, including invitees, participants, owner, comments, name, status, tags, start time, and timestamps.</p></li><li><p><strong>Databases</strong>, including databases, tables, columns, and row data.</p></li></ul><p>The backup also follows selected nested objects. For example, a database backup can include its tables and rows. A chat backup can include its chat messages. A Helpdesk chat backup can include the related chat messages.</p><h2>Incremental by default</h2><p>Daily backups do not need to upload the entire workspace every time. Aamu tracks the latest successful backup timestamp for each backed-up object and uses that to decide which documents have changed.</p><p>When a task, Doc, ticket, row, meeting, or other backed-up object has not changed since the last backup, it can be skipped. When it has changed, Aamu writes a fresh JSON object to the backup bucket.</p><h2>Readable JSON, organized by object path</h2><p>Backup files are written as JSON, not as an opaque database dump. The object key reflects the Aamu object path.</p><pre><code class="language-plaintext">projects/PROJECT_ID.json
docs/DOC_ID.json
tasks/TASK_ID.json
helpdesk_tickets/TICKET_ID.json
dbs/DB_ID/dbtables/TABLE_ID/dbrows/ROW_ID.json</code></pre><p>Open a JSON file from the bucket to inspect the backed-up object.</p><p>It also makes downstream use easier. A backup bucket can feed an audit process, a data lake, a migration tool, or a custom recovery script without first unpacking a monolithic archive.</p><h2>Portable data, including AI-assisted migration</h2><p>Readable JSON makes the backup useful outside Aamu. A team can inspect the files directly, write scripts against them, import selected records into another system, or transform the data into whatever shape the next tool expects.</p><p>This is especially important now that AI can help with migration work. If a team wants to move task history, support tickets, CRM rows, Docs, or meeting notes into another service, an AI-assisted script can read the backup files, map fields, normalize content, and prepare imports for the target system.</p><h2>Media referenced from content</h2><p>Workspace content often includes images or file references. During backup, Aamu can process image references in HTML content and copy those media objects into the backup bucket under a stable media path.</p><p>That means backed-up Docs, posts, tasks, or other HTML content are less dependent on the original media location. The JSON can point to media stored alongside the backup data.</p><h2>How the storage connection works</h2><p>A backup connection is configured per team. Aamu needs the S3-compatible endpoint, bucket name, access key, secret key, and optionally region and path-style mode.</p><p>Path-style mode is useful for providers that expect bucket names in the URL path instead of as a virtual host. Region is optional because some S3-compatible providers require it and some do not.</p><p>Before writing backup objects, Aamu checks access to the configured bucket. If the bucket cannot be reached, credentials are wrong, or the provider rejects the request, the backup run records an error instead of silently pretending everything worked.</p><h2>Daily schedule</h2><p>The backup worker runs automatically for enabled teams. On server start it performs a backup run, and then it repeats the backup process every 24 hours.</p><p>Each enabled team's backup is queued during the run. Teams with incomplete storage configuration are skipped until the endpoint, bucket, and credentials are present.</p><h2>Operational safety details</h2><p>Backup systems should fail loudly enough to be useful. Aamu records backup errors on the team's backup configuration when a run fails. The backup process also limits repeated errors so one broken object or storage problem does not cause an uncontrolled failure loop.</p><p>Uploads are logged with progress during larger runs. If there are no changed objects, the run completes without uploading new JSON files.</p><p>A full backup can also reset the stored backup timestamps for a team, which forces Aamu to treat existing objects as needing to be exported again.</p><h2>What this is not</h2><p>Daily S3-compatible backups are not a replacement for every reliability layer. They do not remove the need for primary database backups, application monitoring, access control, or retention planning.</p><h2>Related articles</h2><ul><li><a href="/blog/posts/outbound-webhooks-in-aamuapp-real-time-events-tasks-helpdesk-email/">Outbound webhooks in Aamu.app: real-time events for tasks, Helpdesk, email, and more</a></li><li><a href="/blog/posts/using-third-party-apis-through-aamuapp-ai/">Using third-party APIs through Aamu.app AI</a></li><li><a href="/blog/posts/ai-commands-in-aamuapp-turning-comments-into-workspace-actions/">AI commands in Aamu.app: turning comments into workspace actions</a></li><li><a href="/blog/posts/all-the-productivity-apps-you-could-think-of-100/">144 productivity apps in 2026</a></li><li><a href="/blog/posts/internal-links-in-aamuapp/">Internal Links in Aamu.app</a></li></ul>
