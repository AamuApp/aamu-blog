# Creating survey forms with Aamu.app Form BuilderHow to create survey forms with Aamu.app Form Builder and store responses in a connected database for follow-up and reporting.Published: 2025-06-02


<p><strong>Short answer:</strong> How to create survey forms with Aamu.app Form Builder and store responses in a connected database for follow-up and reporting.</p>
<p>Build surveys, feedback forms, signup forms and internal request forms with Aamu Forms. Published forms accept public submissions and store each response as a row in an Aamu Database table.</p><h2>Create a new form</h2><p>Open Forms in the project that should own the survey, then create a form. Project membership controls which team members can work with it.</p><p>A new form starts as a draft. Give it a clear title and, if useful, a short description that tells respondents what the form is for. For a survey, this is usually enough:</p><ul><li><p>what you are asking about,</p></li><li><p>how long it will take, and</p></li><li><p>what happens after the respondent submits it.</p></li></ul><h2>Add survey fields</h2><p>Use <strong>Add new field</strong> to build the form. The current field types cover the common survey cases:</p><ul><li><p><strong>Text answer</strong> for short free-text answers,</p></li><li><p><strong>Paragraph</strong> for longer open answers,</p></li><li><p><strong>Choice</strong> for radio buttons, dropdowns, or checkboxes,</p></li><li><p><strong>Date/time</strong> for dates, times, or date-time values, and</p></li><li><p><strong>File upload</strong> for attaching files to the response.</p></li></ul><p>Each field can have a title, description, placeholder text where relevant, and a required toggle. Choice fields can be one-choice radio buttons, one-choice dropdowns, or multiple-choice checkboxes.</p><p>For surveys, avoid making every field required. Required fields are useful for must-have data such as email address or consent, but too many required fields make people abandon the form.</p><h2>Think in database columns</h2><p>When you publish a form, Aamu connects the form to a database table. The form fields become structured columns, and each submission creates a row.</p><p>This has two practical consequences:</p><ul><li><p>After a field has been published into the database, its type is part of the response structure.</p></li><li><p>If you change a published form, publish the new elements so the database table and public form stay in sync.</p></li></ul><p>Publish structural changes to update both the public form and its database table.</p><h2>Configure form settings</h2><p>Open the form Settings tab before publishing. The useful settings are:</p><ul><li><p><strong>Short url</strong> for a cleaner public link,</p></li><li><p><strong>Thank-you page</strong> for redirecting successful submissions,</p></li><li><p><strong>Error page</strong> for redirecting failed submissions,</p></li><li><p><strong>Submit button text</strong> for matching the form's purpose, and</p></li><li><p><strong>Custom CSS</strong> for adjusting the public form's appearance.</p></li></ul><p>If you do not set custom thank-you or error pages, Aamu uses default pages. For public surveys, a custom thank-you page is often worth adding because it can tell the respondent what happens next.</p><h2>Publish and share the form</h2><p>Publish the form when it is ready. After publishing, Aamu shows a <strong>View form</strong> link. The public URL uses this shape:</p><pre><code class="language-plaintext">https://YOUR_AAMU_SUBDOMAIN.aamu.app/shared/form/FORM_ID_OR_SHORT_URL</code></pre><p>Use the generated link from Aamu. If you configured a short url, the public link can use that instead of the raw form id.</p><p>Before sending the link to real respondents, submit the form once yourself. Check the thank-you page, required fields, choice labels, file upload fields if any, and the resulting response row.</p><h2>Review responses</h2><p>Once the form is public, the form header includes a Responses tab. Aamu shows both a summary view and the underlying database connection.</p><p>The summary view is useful for quick survey reading: choice fields can be charted, and text fields can be reviewed as collected answers. The details view shows the actual database rows. Aamu also links directly to the database table, where you can work with the responses like any other database data.</p><p>This is helpful when a survey turns into work. For example:</p><ul><li><p>a feedback form can create follow-up tasks,</p></li><li><p>a sign-up form can become a customer or lead list,</p></li><li><p>a bug-report form can be triaged in a database view, and</p></li><li><p>a file-upload form can keep attachments connected to the response row.</p></li></ul><h2>Automate after responses arrive</h2><p>Because responses are stored in a database table, you can use database automations for follow-up work. For example, a response can lead to a task, a notification, a status change, or another internal workflow.</p><h2>Using the Forms API</h2><p>For normal public surveys, use the published form link. A browser visitor does not need an API key to submit the public form.</p><p>For integrations, the authenticated Forms API can now manage the Form lifecycle as well as responses:</p><pre><code class="language-plaintext">GET   /api/v1/forms/
POST  /api/v1/forms/
GET   /api/v1/forms/{id}
PATCH /api/v1/forms/{id}
POST  /api/v1/forms/{id}/submissions</code></pre><p><code>POST /api/v1/forms/</code> creates a Form with typed questions. Set <code>publish</code> to <code>true</code> when the integration should also create the backing database and table and make the Form public immediately.</p><pre><code class="language-plaintext">POST /api/v1/forms/
x-api-key: YOUR_API_KEY
x-project-id: YOUR_PROJECT_ID
Content-Type: application/json

{
  "name": "Contact Form",
  "publish": true,
  "fields": [
    { "title": "Name", "type": "short_text", "required": true },
    { "title": "Email address", "type": "email", "required": true },
    { "title": "Message", "type": "long_text" }
  ]
}</code></pre><p><code>PATCH /api/v1/forms/{id}</code> updates the name, description, submit button, or question list. Supplying <code>fields</code> replaces the Form's question list. Set <code>publish: true</code> to publish a draft or add newly defined fields to an already published Form's database table.</p><p>The internal Aamu AI uses these same OpenAPI operations. A request such as “Create a Form called Contact Form that asks for a name and email address” can therefore create the Form with the signed-in user's project access and open it in the Form editor.</p><p>Use the API when another system needs repeatable Form setup or structured submissions. Use the public form when a person is filling in a survey in the browser.</p><h2>A simple survey checklist</h2><ol><li><p>Create the form in the right project.</p></li><li><p>Add a short title and description.</p></li><li><p>Add fields with clear labels.</p></li><li><p>Mark only the necessary fields as required.</p></li><li><p>Configure the short url and thank-you page.</p></li><li><p>Publish the form.</p></li><li><p>Open the public link and submit a test response.</p></li><li><p>Check the Responses tab and the database row.</p></li><li><p>Add automations if responses should trigger follow-up work.</p></li></ol><h2>Related articles</h2><ul><li><a href="/blog/posts/from-form-submission-to-follow-up-workflows-with-aamuapp/">From form submission to follow-up: workflows with Aamu.app</a></li><li><a href="/blog/posts/creating-a-contact-form-with-aamuapp/">Creating a contact form with Aamu.app</a></li><li><a href="/blog/posts/database-automations-with-aamuapp/">Database automations with Aamu.app</a></li><li><a href="/blog/posts/aamuapp-databases-practical-feature-guide/">Aamu.app Databases: a practical feature guide</a></li><li><a href="/blog/posts/creating-a-blog-with-aamuapp/">Creating a blog with Aamu.app</a></li></ul>
